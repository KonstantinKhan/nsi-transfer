 # NsiTransfer

**NsiTransfer** — это бэкенд-сервис, предназначенный для интеграции с PDM-системой **Ascon Polynom**. Его основная задача — синхронизация нормативно-справочной информации (НСИ) из Полинома во внешние системы-потребители.

Сервис предоставляет RESTful API для управления процессом синхронизации, конфигурацией, аутентификацией, а также для мониторинга состояния операций в реальном времени с использованием технологии Server-Sent Events (SSE).

## Ключевые особенности

- **Синхронизация данных с Polynom API**: Автоматический и ручной запуск сбора измененных данных за определенный период. Система автоматически определяет временное окно для следующей синхронизации на основе истории предыдущих запусков.
- **Интеграция с RabbitMQ**: Публикация собранных данных в очередь для дальнейшей обработки внешними системами. Реализован надежный механизм публикации с подтверждениями (`Publisher Confirms`), ретраями и обработкой сбоев соединения.
- **Динамическая конфигурация**: API для чтения и изменения конфигурации приложения "на лету" без перезапуска сервиса. Включает рекурсивную валидацию для обеспечения целостности и корректности всех настроек.
- **Аутентификация и управление сессией**: Безопасная аутентификация в Polynom API с использованием JWT. Токены доступа и обновления хранятся в безопасных `HttpOnly` cookie, что защищает от XSS-атак.
- **Мониторинг в реальном времени**: Поддержка **Server-Sent Events (SSE)** для отслеживания прогресса длительных операций синхронизации из веб-интерфейса.
- **Фоновые задачи**: Архитектура для выполнения фоновых задач (например, отправка email-уведомлений об ошибках) через внутреннюю очередь, что не блокирует основной поток выполнения.
- **Администрирование**: API для настройки ключевых параметров, таких как целевой справочник в Полиноме для синхронизации.
- **Подробное логирование**: Все ключевые операции и события в системе логируются для упрощения отладки и мониторинга.

## Технологический стек и архитектура

### Технологии

- **Платформа**: .NET 8 (ASP.NET Core)
- **Язык**: C# 12
- **База данных**: Entity Framework Core (для хранения истории и состояния синхронизаций)
- **Брокер сообщений**: RabbitMQ
- **Документация API**: Swashbuckle (Swagger/OpenAPI)

### Архитектура

Приложение построено на основе классической **многослойной архитектуры (Layered Architecture)** для четкого разделения ответственности.

```
┌───────────────────┐
│ Presentation Layer│ (NsiTransfer)
└───────────────────┘
         ↓
┌───────────────────┐
│    BLL Layer      │ (NsiTransfer.BLL)
└───────────────────┘
         ↓
┌───────────────────┐
│    DAL Layer      │ (NsiTransfer.DAL)
└───────────────────┘
         ↓
┌───────────────────┐
│   Contract Layer  │ (NsiTransfer.Contract)
└───────────────────┘
```

- `NsiTransfer.Contract`: "Контрактный" проект. Содержит общие модели данных (DTO), интерфейсы, перечисления и модели конфигурации. Не имеет зависимостей от других слоев проекта.
- `NsiTransfer.DAL` (Data Access Layer): Слой доступа к данным. Отвечает за взаимодействие с базой данных (EF Core) и внешними сервисами, такими как Polynom API (через HTTP-клиенты) и RabbitMQ.
- `NsiTransfer.BLL` (Business Logic Layer): Слой бизнес-логики. Содержит основную логику приложения: Use Cases, сервисы, фоновые задачи. Оркестрирует взаимодействие между DAL и Presentation.
- `NsiTransfer` (Presentation Layer): Слой представления. Реализован как проект ASP.NET Core Web API. Содержит контроллеры, обработчики аутентификации, middleware и конфигурацию DI-контейнера (`Program.cs`).

## Структура проекта

Проект состоит из нескольких под-проектов, определенных в файле `NsiTransfer.slnx`:

- `docker-compose.dcproj`: Проект для поддержки Docker Compose в Visual Studio.

## Конфигурация

Конфигурация приложения осуществляется через файл `appsettings.json` и его специфичные для окружения версии (например, `appsettings.Development.json`).

Основные секции конфигурации:

- `ConnectionStrings`: Строки подключения к базе данных.
- `SmtpSettings`: Параметры SMTP-сервера для отправки email-уведомлений.
- `RabbitMqCreds`: Учетные данные для подключения к RabbitMQ.
- `AppConfiguration`: Основная конфигурация приложения, которая также может управляться через API (`/api/configuration`).
  - `TargetReferenceNode`: Целевой узел-справочник в Полиноме, который является областью для синхронизации.
  - `RabbitMqQueues`: Имена обменника (exchange) и очередей в RabbitMQ.
  - `RabbitMqRetryParams`: Политика повторных попыток при публикации сообщений в RabbitMQ.
  - `PolynomApiSyncOptions`: Параметры процесса синхронизации (например, интервал запуска фоновой задачи).
  - `EmailNotifications`: Список email-адресов для получения уведомлений об ошибках.

**Важно:** Для корректной работы приложения необходимо, чтобы все обязательные поля в конфигурации были заполнены. Система использует рекурсивную валидацию (`AppConfigurationValidator`) при старте и при обновлении через API, чтобы предотвратить запуск с некорректными настройками.

## Сборка и запуск

### Предварительные требования

- .NET 8 SDK
- Docker (для запуска RabbitMQ и, возможно, базы данных)
- Доступ к экземпляру Polynom API.

### Запуск

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <repository-url>
    cd NsiTransfer
    ```

2.  **Настройте внешние зависимости:**
    Запустите RabbitMQ и базу данных (например, PostgreSQL) с помощью Docker или используйте существующие экземпляры.

3.  **Создайте файл конфигурации:**
    Создайте файл `NsiTransfer/appsettings.Development.json` и заполните его необходимыми значениями, скопировав структуру из `appsettings.json`. Как минимум, нужно указать:
    - `ConnectionStrings`
    - `RabbitMqCreds`
    - `SmtpSettings`
    - URL API Полинома

4.  **Запустите приложение:**
    Вы можете запустить проект из вашей IDE (Visual Studio, JetBrains Rider) или через командную строку:
    ```bash
    dotnet run --project NsiTransfer/NsiTransfer.csproj
    ```

5.  **Откройте интерфейс API:**
    После запуска сервис будет доступен по адресу, указанному в `launchSettings.json` (например, `https://localhost:7141`).
    Интерактивная документация Swagger UI будет доступна по адресу `https://localhost:7141/swagger`.

### Post-Build Events

В проектах могут использоваться **Post-Build** события для автоматизации задач после сборки. Например, скрипт может копировать необходимые DLL-библиотеки (такие как `Ascon.Polynom.Web.Api.Data.dll`) из одного места в выходную директорию сборки (`bin/Debug/...`).

Это обеспечивает наличие всех зависимостей во время выполнения, особенно для библиотек, которые не управляются через NuGet или требуют специфического расположения. Анализ конкретных скриптов невозможен без доступа к файлам `.csproj`, но их основная цель — подготовить окружение для запуска или развертывания.

## Обзор API

Сервис предоставляет несколько групп эндпоинтов, сгруппированных по контроллерам:

- `api/auth`:
  - **Назначение:** Аутентификация в API Полинома, обновление и отзыв токенов.
  - **Ключевые методы:** `signin`, `signout`, `refresh-token`.

- `api/configuration`:
  - **Назначение:** Управление конфигурацией приложения в реальном времени.
  - **Ключевые методы:** `GET /`, `PUT /`, а также методы для получения и обновления отдельных секций (`/target-reference-node`, `/rabbitmq-queues` и т.д.).

- `api/admin-panel`:
  - **Назначение:** Методы для административной настройки интеграции.
  - **Ключевые методы:** `GET /reference/first-layer` (для выбора целевого справочника).

- `api/polynom-sync`:
  - **Назначение:** Основной функционал по запуску и мониторингу синхронизации.
  - **Ключевые методы:**
    - `POST /start-data-collection-and-wait`: Запускает синхронизацию и ожидает ее завершения.
    - `POST /start-data-collection-in-background`: Запускает синхронизацию в фоновом режиме.
    - `GET /listen-for-sync-events`: SSE-эндпоинт для подписки на события конкретной синхронизации.
    - `GET /listen-for-all-sync-events`: SSE-эндпоинт для подписки на события всех синхронизаций.
    - `GET /sendings`: Получение истории запусков с пагинацией.

- `api/polynom-utils`:
  - **Назначение:** Вспомогательные методы для прямого взаимодействия с API Полинома.
  - **Ключевые методы:** Поиск объектов по дате изменения или по части имени.
